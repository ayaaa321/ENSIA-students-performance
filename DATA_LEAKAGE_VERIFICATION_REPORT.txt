2. DERIVED/AGGREGATED FEATURES (Correctly Dropped as Leakage):
──────────────────────────────────────────────────────────────
These are CALCULATED FROM THE TARGET:
• assignment_1_n, assignment_2_n, assignment_3_n (count of assignments)
• module_score_sum, module_score_total (sums of module scores)
• final_grade_average, final_grade_mean (duplicates of target)
• attendance_count, attendance_total (totals)

Why these are LEAKAGE:
  Problem 1: DERIVED AFTER ASSESSMENT
  ───────────────────────────────────
  These columns are calculated/aggregated AFTER students take exams:
  • assignment_n counts = # of assignments completed (happens during course)
  • scores_sum = sum of all scores (only known AFTER grading)
  • final_grade_average = calculated FROM individual grades
  
  If we train on these:
  ❌ Model learns from future information
  ❌ Performance in training is unrealistically high
  ❌ Real predictions on new students fail
  
  Example of Leakage:
  - Student hasn't taken exams yet
  - We have: stress_level=high, study_hours=3, math_level=good
  - We DON'T have: assignment_1_n=2, scores_sum=48 (not completed yet!)
  - Model trained on assignment_n learns spurious correlation
  - Prediction fails on new students

  Problem 2: PERFECT/NEAR-PERFECT CORRELATION WITH TARGET
  ────────────────────────────────────────────────────────
  • module_score_sum = directly related to final average
  • final_grade_count = only filled if assessment complete
  • These are EQUIVALENT to target, not predictors

  Problem 3: ONLY AVAILABLE AFTER OUTCOME
  ─────────────────────────────────────────
  In production:
  - We assess a student BEFORE they take the exam
  - We have stress, programming_exp, study_hours, etc.
  - We DON'T have assignment_n or scores_sum
  - Model trained on these features can't work in production

Status: ✅ CORRECT TO DROP - These are textbook data leakage

Why Derived Features Cause Leakage:
===================================

Example 1: ASSIGNMENT COUNTS
──────────────────────────
Feature: assignment_1_n (count of assignment 1 submissions)
Problem: 
  • Used to count assignments per module
  • Only meaningful AFTER assignment period
  • Correlates with attendance (during-course variable)
  • Predicts performance by "revealing" course progress

Training data (LEAKED):
  Student A: stress=high, assignment_1_n=5, avg_grade=14
  Model learns: assignment_1_n=5 → avg_grade=14 (FALSE!)

Production (FAILS):
  New student B: stress=high, assignment_1_n=??? (not yet assigned)
  Can't make prediction → Model breaks

Example 2: SCORE SUMS
─────────────────────
Feature: module_score_sum (sum of all module scores)
Problem:
  • Calculated by: SUM(module_1_score, module_2_score, ...)
  • Only available AFTER all assessments complete
  • Is essentially a linear combination of target

Training data (PERFECT CORRELATION):
  Correlation(module_score_sum, final_avg) ≈ 0.98
  Model thinks: "This feature explains everything!"

Production (USELESS):
  New student: module_score_sum = ??? (exam not given yet)
  Prediction impossible with this feature

Example 3: GRADE DUPLICATES
───────────────────────────
Feature: final_grade_average (same as target!)
Problem:
  • Used for some calculations in preprocessing
  • Is literally the SAME as what we're predicting
  • 100% correlation with target

This is like:
  Training: "Predict student final grade"
  Model learns: "final_grade = final_grade" ✓ (99% accuracy!)
  In production: "Predict student grade" 
  Model: "I can only predict it if you tell me the grade first" ✗


How Leakage Manifests:
======================
1. TRAINING PHASE (Optimistic):
   Model sees derived features with high correlation
   Reports accuracy: 0.95 (unrealistic!)
   
2. VALIDATION PHASE (Still Works):
   Val set also has all derived features
   Reports: 0.92 accuracy (still unrealistic)
   
3. PRODUCTION (Disaster):
   New student data missing derived features
   Model can't make predictions
   OR makes wrong predictions (learned wrong relationships)

4. MODEL MONITORING (Crisis):
   Actual performance: 0.45 accuracy
   Predicted performance: 0.92 accuracy
   "Why is model performing so badly?" ← Leakage discovered too late


How We Prevented Leakage:
========================
✓ Identified all derived features (suffix _n, _sum, _total, _count)
✓ Removed them before feature engineering
✓ Kept only pre-assessment features (available at prediction time)
✓ Verified no high correlations with target (max ~0.6)
✓ Tested on held-out k-fold splits (detected any remaining issues)
✓ Performance realistic for problem difficulty (MAE ~1.21 on 10-16 scale)
