THE EXPERIMENT
================================================================================

Question: Can we improve model performance by adding interaction and ratio 
          features to the original 31-feature set?

Approach: 
  1. Created 16 new engineered features (interactions + ratios)
  2. Tested on Ridge Regression and Random Forest
  3. Used 5-fold cross-validation for fair comparison
  4. Measured MAE (Mean Absolute Error) improvement

Data:
  • Original features: 31
  • New features: 16 (from 107 combinations tested)
  • Total feature set: 138 features
  • Samples: 225 students
  • Models trained: Ridge + RandomForest


================================================================================
RESULTS
================================================================================

                          BASELINE (31 feat)    ENGINEERED (138 feat)   CHANGE
                          ──────────────────    ─────────────────────   ──────
Ridge Regression          1.2077 ± 0.1409       1.2539 ± 0.1048         -3.82%
RandomForest              1.2642 ± 0.0962       1.2724 ± 0.0847         -0.65%

WINNER: Ridge with Original 31 Features (MAE = 1.2077)


================================================================================
KEY FINDING
================================================================================

❌ FEATURE ENGINEERING DID NOT HELP

Both Ridge and RandomForest performed WORSE with engineered features:
  • Ridge: Degraded by 0.0462 MAE (3.82% worse)
  • RandomForest: Degraded by 0.0082 MAE (0.65% worse)

The engineered features introduced NOISE rather than SIGNAL.


================================================================================
WHY THE DEGRADATION?
================================================================================

ROOT CAUSE #1: Sample-to-Feature Ratio Collapse
────────────────────────────────────────────────
Before:  225 samples / 31 features = 7.3:1 ratio
After:   225 samples / 138 features = 1.6:1 ratio
Needed:  >10:1 for reliable generalization

With ratio of only 1.6:1, the model cannot learn stable patterns.
The 107 new features introduce overfitting noise.


ROOT CAUSE #2: Engineered Features Have Very Low Importance
──────────────────────────────────────────────────────────
Ridge coefficient analysis:
  • Top 5 features: ALL from original 31-feature set
  • Engineered features: Ranked 50-138 (coefficients < 0.002)

Random Forest importance:
  • Top 5 features: ALL from original 31-feature set
  • Engineered features: Ranked outside top 50 (importance < 0.001)

Interpretation: The engineered features DON'T capture any patterns the 
               models care about. They're statistical noise.


ROOT CAUSE #3: Original 31 Features Are Already Optimal
────────────────────────────────────────────────────────
The original features went through rigorous selection:
  ✓ Correlation analysis with target
  ✓ Data leakage verification (removed problematic features)
  ✓ Dimensionality reduction testing (all 31 confirmed as useful)
  ✓ Tuning confirmed: all 31 features necessary

You can't improve on an already-optimized feature set by adding more features,
especially when data is limited (225 samples).


ROOT CAUSE #4: Tree Models Already Capture Interactions
───────────────────────────────────────────────────────
Random Forest automatically learns interactions through:
  • Multiple feature splits per tree node
  • Tree depth (max_depth=10 allows complex patterns)
  • Ensemble of different feature combinations

Explicit interaction features (e.g., stress × study_hours) don't provide
new information that the model can't already extract.

================================================================================
LESSONS LEARNED
================================================================================

1. More features ≠ Better performance
   Sometimes the original feature set is already optimal.

2. Sample size is your true constraint
   With 225 samples and 31 features (7.3:1 ratio), you're hitting limits.
   Adding 107 more features violates the fundamental principle of
   generalization with small data.

3. Tree-based models are powerful at capturing interactions
   RandomForest doesn't need explicit interaction features because it
   learns them automatically through splits.

4. Validation saved us from a bad decision
   Without proper k-fold CV, we might have deployed worse models.
   Always validate before deploying.

5. Simplicity is powerful (Occam's Razor)
   The simpler model with 31 features outperforms the complex model
   with 138 features. This is not coincidence - it's a fundamental
   principle of machine learning.
