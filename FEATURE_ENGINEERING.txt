3.A LEAKAGE REMOVAL
====================

Leakage: Using information that would not be available at prediction time.

Dropped ALL average/mean/avg columns EXCEPT the target:
   - Dropped: 1y_all_modules_avg, 1y_programming_average, 1y_math_average, etc.
   - Dropped: 2y_average, 3y_average (when predicting for 1Y; kept only target)
   - Reason: These are derived from the same grades we're trying to predict;
             using them would be "cheating" (data leakage)

[4] FEATURE TRANSFORMATION PIPELINE
================================================================================

All data passes through a unified preprocessing pipeline fitted on concatenated
training data from ALL cohorts (1Y, 2Y, 3Y).

STEP-BY-STEP TRANSFORMATION:
============================

Step 1: COLUMN NAME STANDARDIZATION
   Input:  "What's your level of motivation for joining ENSIA?"
   Process: 1. Lowercase
            2. Replace special chars with underscore
            3. Truncate to max 40 characters if too long
   Output: "what_s_your_level_of_motivation_for_jo"


Step 2: LEAKAGE & REDUNDANCY FILTERING
   Process: Drop all columns flagged as leakage or redundant (see section 3)
   Effect: Reduces feature count from ~80 → ~35 raw features


Step 3: FREQUENCY ENCODING (High-cardinality categorical, >10 unique values)
   Columns affected: 3 columns
   Process:
      1. Count frequency of each unique value in training data
      2. Create value → frequency mapping (normalize to 0–1 range)
      3. Replace text value with its frequency score
   
   Example:
      Original: "Learning by practicing"
      Frequency map: {"Learning by practicing": 0.068, "Online courses": 0.040, ...}
      Encoded value: 0.068
      
   Why: Reduces dimensionality (1 column per feature, not 50+ one-hot columns).
        Captures category prevalence (more common responses get higher weight).


Step 4: ONE-HOT ENCODING (Low-cardinality categorical, ≤10 unique values)
   Columns affected: 20 columns
   Process:
      1. Identify all unique values in training data
      2. Create one binary column per unique value
      3. Set to 1 if value matches, 0 otherwise
   
   Example (gender, 3 unique values):
      Original values: "Male", "Female", "Other"
      After encoding:
         gender_male: [1, 0, 0]
         gender_female: [0, 1, 0]
         gender_other: [0, 0, 1]
      
   Why: Prevents artificial ordering (Male=1 < Female=2 implies ordering).
        Allows model to learn independent effect of each category.


Step 5: NUMERIC IMPUTATION
   Columns affected: 8 numeric columns
   Process: For each missing value (NaN), fill with column mean
   
   Example:
      Before: [5.0, NaN, 8.0, 3.0, NaN]
      Mean: (5+8+3)/3 = 5.33
      After: [5.0, 5.33, 8.0, 3.0, 5.33]
      
   Why: Preserves sample count. Uses reasonable default (average behavior).


Step 6: NUMERIC STANDARDIZATION (StandardScaler)
   Columns affected: All numeric columns (8 original + 8 from one-hot encoding)
   Process: z = (x - mean) / std
   
   Example (motivation, originally 1–10):
      Original values: [5, 7, 8, 3, 6]
      Mean: 5.8, Std: 1.64
      Standardized: 
         5 → (5-5.8)/1.64 = -0.49
         7 → (7-5.8)/1.64 = 0.73
         8 → (8-5.8)/1.64 = 1.34
         3 → (3-5.8)/1.64 = -1.71
         6 → (6-5.8)/1.64 = 0.12
      
   After transformation: mean ≈ 0.0, std ≈ 1.0
   
   Why: All features on same scale. Prevents features with larger ranges
        (e.g., study hours: 0–50) from dominating features with smaller ranges
        (e.g., satisfaction: 1–10). Ridge/RandomForest benefit from scaling.


Step 7: ID COLUMN REMOVAL
   Process: Drop all ID-like columns (student_id, record_id, etc.)
   Why: IDs are not predictive; would cause data leakage if model learns
        to memorize student IDs.

[5] UNIFIED PREPROCESSOR (KEY ARCHITECTURAL DECISION)
================================================================================

PROBLEM: Train/test on 1Y, 2Y, 3Y cohorts separately → different scalings,
         different one-hot categories, unfair comparison.

SOLUTION: Fit preprocessor ONCE on all training data concatenated.

PROCESS:
1. Concatenate train sets from 1Y, 2Y, 3Y (225 samples total)
2. Fit frequency encoder on concatenated data → 1 frequency map
3. Fit one-hot encoder on concatenated data → consistent categories
4. Fit standard scaler on concatenated data → 1 mean & std per feature
5. Save preprocessor + frequency maps + fit_columns metadata
6. Apply SAME preprocessing to each cohort's test set

BENEFIT:
   ✓ Fair comparison: all cohorts use identical feature scales
   ✓ Stable encoding: categories seen in training are consistently encoded
   ✓ Reproducible: can load saved preprocessor for future predictions


================================================================================
[6] WHY EACH ENCODING METHOD
================================================================================

PROBLEM: Raw survey responses are mixed types (text, numeric, categories).
         Models expect numeric input; features at different scales conflict.

SOLUTION: Encoding strategy tailored to each data type.


FREQUENCY ENCODING (high-cardinality categorical):
   Problem: 50+ unique values → one-hot would create 50+ sparse columns
   Solution: Map each value to its frequency (0.0–1.0)
   Trade-off: Loses category identity but preserves prevalence signal
   When: >10 unique values
   Examples in data: Learning methods (62 types), resources (44 types),
                     problems (33 types)


ONE-HOT ENCODING (low-cardinality categorical):
   Problem: Gender [Male=1, Female=2, Other=3] implies Male < Female < Other
   Solution: Create binary columns (no artificial ordering)
   Trade-off: Increases dimensionality but preserves category independence
   When: ≤10 unique values
   Examples in data: Gender (3), year (3), study location (5), etc.


STANDARDIZATION (numeric):
   Problem: Different scales (motivation: 1–10 vs. study hours: 0–50)
            Ridge regularization penalizes large weights; needs fair scale
   Solution: z = (x - mean) / std → all features mean=0, std=1
   Trade-off: Loses interpretability (units) but improves model stability
   When: All numeric features
   Examples in data: Motivation, satisfaction, stress, skills, etc.


MEAN IMPUTATION (missing values):
   Problem: Incomplete survey responses
   Solution: Fill missing with column mean (default to average behavior)
   Trade-off: Introduces bias (assumes missing ≈ average) but preserves n
   When: Any missing numeric value
   Result: No samples dropped; maximum training data used

[11] KEY INSIGHTS & DECISIONS
================================================================================

WHY UNIFIED PREPROCESSING?
   Different scaling across cohorts would make comparisons unfair.
   By fitting once on all data, all cohorts use same scale/encoding.

WHY FREQUENCY ENCODING FOR 3 COLUMNS?
   62 unique learning methods → one-hot would create 62 sparse columns.
   Frequency encoding reduces to 1 column, captures category prevalence.

WHY NO EXPLICIT NUMERIC FEATURES IN fit_columns?
   The numeric columns (8) are part of one-hot transformation output.
   They are scaled by StandardScaler; their names appear in fit_columns
   (e.g., 'rate_your_satisfaction_with_the_school_s').

WHY DROP *_n COLUMNS?
   These are just counts of responses per category.
   Not meaningful for prediction (e.g., "how many programming modules" is
   redundant with program structure, not student-specific behavior).

WHY POOLED TRAINING?
   Cohorts 2Y and 3Y have very few samples (70, 8 total).
   Pooling (225 samples) improves model stability and avoids overfitting.
   Fair comparison: same training signal across cohorts at test time.

[12] LIMITATIONS & FUTURE IMPROVEMENTS
================================================================================

CURRENT LIMITATIONS:
   1. Survey data may have response bias (students may not answer truthfully)
   2. Small cohort sizes (especially 3Y: n=10) make metrics unreliable
   3. Frequency encoding loses category identity (no interpretability)
   4. Feature engineering assumes survey questions are valid proxies for
      performance (unclear causal relationship)

POTENTIAL IMPROVEMENTS:
   1. Add external features: prior GPA, attendance, module-specific grades
   2. Use SHAP or permutation importance to identify most predictive features
   3. Implement k-fold cross-validation for more robust metric estimation
   4. Explore interaction terms (e.g., motivation × study hours)
   5. Investigate label noise (validate target values)
   6. Re-save preprocessor in current scikit-learn version (avoid version warnings)
